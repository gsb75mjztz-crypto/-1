# Handover Notes

One file per milestone, written so a new engineer (human or AI) can pick up this project without re-reading the full build history. `/docs` is still the source of truth for *what the product should be*; this folder is the record of *what actually happened, in what order, and why* — the two diverge in places (see `Milestone-3.md` and the Project Health Review), and that gap is exactly what these notes exist to surface.

Each completed milestone's file covers: what shipped, the non-obvious decisions made along the way, the audit history (findings and how they were resolved), and open items carried forward. The next milestone's file is a forward-looking kickoff brief, not a retrospective — written before that work starts, so scope and dependencies are explicit up front rather than reconstructed after the fact.
